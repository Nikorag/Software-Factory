# ADR 0015: Haiku-written implementer prompt by default; Spec Kit is a per-profile option; PR merge conflicts are resolved automatically

Spec Kit gave every ticket the same ceremony: analyst, four generation steps, an independent spec review, validation, remediation, converge passes and a tasks gate. For most tickets that bought little and cost most of the run time, and it required `.specify/` in every repository.

Decision:
- **`workflow.planning_mode`** (factory.yaml, per profile): `haiku_prompt` (default) or `speckit`. In `haiku_prompt` mode `REQUIREMENTS_ANALYSIS` is one read-only Haiku run that inspects the repository and writes the implementer's prompt and acceptance criteria; it never implements. The Spec Kit stages are skipped by the workflow (`nextStage`), no Spec Kit command runs and no spec artefacts exist. The implementer does one run from the prompt; the converge loop and the tasks gate do not apply; the final gate checks the acceptance criteria instead of FR-/SC- ids. Everything that protects the result is shared by both modes: sandboxed checks, independent and Claude review, fix cycles, secrets scan, protected paths, final gates, PR-only delivery. `speckit` mode is unchanged.
- **Merge conflicts are routine, not an escalation.** When the PR reports `CONFLICTING`, `CONFLICT_RESOLUTION` merges the fetched target branch into the job branch (merge, not rebase: a rebase would need a force-push, which is forbidden), the implementer resolves conflicts with both sides in view, and the normal flow re-verifies everything, pushes without force and re-runs the PR checks. It is bounded (`workflow.max_conflict_resolutions`), logged as decisions, outside the fix-cycle budget (the stage bounds itself; the engine's directed `remediate { to }` records a `stage.redirect`), and stops for a human only on a genuine ambiguity, a protected-path conflict or exhaustion.

Consequences: existing profiles without the key move to `haiku_prompt`; set `planning_mode: speckit` to keep the old flow. The `specKit` flag on a project now only decides whether validation warns about a missing `.specify/` in `speckit` mode.
