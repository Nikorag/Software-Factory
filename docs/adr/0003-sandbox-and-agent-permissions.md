# ADR 0003: Confine project code with sandbox-exec; confine agents with verified permission rules
**Context.** Agents and the project code they write run as the user. **Decisions.** (1) The factory runs project commands only under macOS `sandbox-exec`: no network (installs excepted), writes only in the worktree/temp, no reading of credentials. (2) Agents never run project code directly; their only route is `factory-exec`, whose command text comes from the factory's own config. (3) Agent permissions are explicit per role and **absolute-path anchored** (a shell `cd` silently breaks relative rules); bare `Write`/`Edit`/`Read` are never granted. (4) Every rule was verified against the real CLI, and the live tests in `tests/live` re-verify them after upgrades. (5) The factory re-checks the worktree diff after every agent run, independent of the permission system. **Found by live tests, not by reasoning:** a bare `Write` allowed writing anywhere; `Read` allowed reading anywhere; relative rules broke after `cd`; the first sandbox forbade local Unix sockets (tsx) and npm's cache. **Residual risk:** the Claude Code process itself is not OS-sandboxed (see SECURITY.md).
